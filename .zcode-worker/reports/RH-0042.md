## Objective

Add an explicit household preference that shields plot synopses, episode
thumbnails/previews, and outcome-like description text for unwatched content,
defaulting conservatively, with a deliberate per-item Reveal and a clear
reversible action — delivered as a usable interface on current `main`.

**Objective met.** The shield ships on the demo/jellyfin surfaces that exist on
current main: home hero, home rails (cards), search results, and the detail
modal, with a per-profile toggle in the top bar.

## Before / after

- **Before:** every synopsis and preview image rendered unconditionally; there
  was no watch-state field at all (`MediaItem` carried only playback
  `progress`), no household preference storage, and no per-profile behavior
  beyond a cosmetic name switch.
- **After (default, first load):** hero synopsis replaced by
  “Synopsis hidden — the spoiler shield protects unwatched titles.”, hero
  backdrop hidden, unwatched/unknown-state posters replaced by a shield
  placeholder with a dashed mask outline and a per-card **Reveal** chip.
  Played items render normally with no chip. **Reveal synopsis / Reveal
  spoilers / Reveal** flips one item to visible; **Hide synopsis / Hide
  spoilers / Hide** re-masks immediately. A top-bar **Shield on/off** pill
  (aria-pressed, per profile) disables/re-enables the whole shield; profile
  switches clear reveals and load that profile’s stored preference.

## Watch-state and safety boundaries

- Watch state is **read-only from Jellyfin** (`UserData.Played`), per
  `docs/BASELINE.md`; nothing writes Jellyfin state or its internal database.
- Playback progress alone never marks an item watched (unit-tested).
- Unknown watch state stays protected (unit-tested).
- No real sports outcomes in fixtures: all demo synopses are outcome-safe and
  a regression test rejects score-like patterns (`\d+[-–—]\d+`) in synopses.
- No production access: demo library only (no Jellyfin env vars set); no
  credentials, deployments, merges, or external messages; no PostgreSQL,
  no Jellyfin writes, no production restarts.
- Fail-closed behavior: corrupt/missing storage and unknown preference
  values normalize to the conservative shield (unit-tested).

## Known limitations (honest gaps)

1. **Active profile resets on reload.** The baseline has no session identity;
   profiles are client-side component state, so a reload starts as the
   default profile (V’Ali). Per-profile preferences are still keyed and
   persisted correctly; profile-session persistence is future household-state
   work, not part of this job.
2. **Preference is browser-local** (`localStorage`): it does not roam across
   devices/browsers until server-side household preferences land.
3. **Series-level watch state** follows Jellyfin `UserData.Played` only;
   a series whose episodes are individually watched can still read unplayed
   at series level, so it stays protected (conservative by design).
4. **Masking scope is conservative:** preview imagery is masked for all
   unwatched kinds (movies/episodes/videos), not only episodes, per the
   “default conservatively” requirement; Reveal is one click.
5. **Verification environment:** screenshots show CSS fallback gradients
   where remote poster images (picsum) were unreachable from the sandbox;
   assertions cover the URL/state, not third-party image content.
