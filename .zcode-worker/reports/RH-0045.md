## Why the final pin departs from the frozen 16.3.5

The staged resolution is recorded in full in `docs/SECURITY_UPGRADE.md`:
the advisory database moved after RH-0008 was delivered. At the frozen
16.3.5 pins the audit still reports **6 (5 high, 1 critical)** — Next-core
advisories published after 2026-09-18 (dev-server MCP information disclosure,
metadata image-route `dynamicParams` bypass, SSG/ISR cache poisoning, Image
Optimization SSRF, transitive sharp/source-map-js). npm's own resolution for
every remaining finding is `next@16.4.0`, the same major line. Both states
were installed and audited before departing; 16.4.0 is the minimal pin that
fulfills the job's objective. The 16.3.5 audit state is recorded, not
discarded.

## Residual advisory disposition (5 high, one root cause)

All five findings share one cause: `braces` GHSA-vfj7-8cjw-p6xm
(stack-exhaustion DoS via deeply nested glob patterns) via the dev-only chain
`eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch →
braces`. The installed `braces@3.0.3` is the newest release that exists; the
advisory's vulnerable range is `*` (no patched version published), so no pin
or override can clear it — npm's only suggested "fix" is downgrading
`eslint-config-next` to 14, undoing the upgrade. **Disposition: accepted
residual risk** — lint-toolchain code path only (glob expansion during
`npm run lint`), never exercised by the served application, no
attacker-reachable input. Runtime dependencies (`next`, `pg`, `react`,
`react-dom`, `server-only`) audit clean.
